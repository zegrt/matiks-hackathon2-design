The admin flow, touchpoint by touchpoint

What an admin does in the console from opening it to closing the last ticket, what each control does, what it writes to the support database, and where it leads. Every row works in the prototype. Status names and action names are the schema’s. Nothing in this flow ever sends a message to a user.

3Read the state

Critical · safetyHazard band, wait time. No draft by rule.
Escalate · payments, merchPerson only. The message, then reply or hand off.
AssistDraft with values matched to evidence; confidence under 0.90 or not on the safe list.
Auto-readyOn the safe list at 0.90 or more. One key, or approve the batch.
Agent working / failedLive steps, or the error and a retry note.
Rejected · handed off · replied · closedWhat happened, by whom, and what’s still possible.

4Decide, then next

Approve A · Edit E→ replied, next ticket opens.
Hand off X→ stays triaged, leaves your list.
Reject R · Note N→ status unchanged.
Close C · Reopen O→ closed / back to review.
Undo ZFor 6 seconds after any decision. Recorded as a reopen.

Assumptions to confirm with the devs

Auto drafts need one click. Only console actions move a ticket to replied, so auto-ready tickets wait in their own group with “Approve all”. If the API approves them itself, the group disappears.
Reopen goes to triaged when the ticket has a classification, otherwise open.
Safety tickets are pinned above the score. The score has no severity component.
Rejecting doesn’t re-run the agent. The ticket waits for a person.
Edited text isn’t re-checked by the guardrail. The editor’s checks run in the browser.
Failed runs retry up to 3 times. The prototype shows “attempt 2 of 3”.
